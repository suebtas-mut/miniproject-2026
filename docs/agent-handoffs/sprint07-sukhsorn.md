## Exact local request/response shapes exercised by this client (mock-verified only)
- `GET /schedules?activeOnly=true[&serviceDate=yyyy-MM-dd][&routeId=n]` → `200` **array** of `{schedId, routeId, routeName, serviceDate, departAt, isActive, totalMinutes?, stopCount?, seatsTotal?, seatsBooked?, seatsAvailable?, driver?: {empId, empCode, fullName}, vehicle?: {vehId, plateNo, vtypeId, typeName, capacity, isActive}, stops?: [{stopSeq, stopId, stopName, arriveAt, dwellMinutes}]}`; Bearer required.
- `POST /schedules` body `{routeId, serviceDate, departAt}` (`departAt` = `{serviceDate}T{HH:mm}:00`) → `201` schedule; `409 {code, message}` duplicate route+date+depart; `422 {code: BR02_ARRIVE_MISMATCH, message}` — both messages displayed verbatim, dialog stays open.
- `DELETE /schedules/{schedId}` → `204`; `409 {code: BOOKINGS_EXIST, message}` when bookings exist (message shown as snackbar, no reload).
- `PUT /schedules/{schedId}/assignments` body **required** `{empId, vehId}` → `200 {schedId, driver, vehicle}`; `400 {code: NOT_A_DRIVER}`, `409 {code: BR04_DRIVER_CONFLICT, message}` — conflict message displayed verbatim in dialog (`assign-error`), dialog stays open, list not reloaded (Conflict Alert behavior).
- `GET /vehicle-types` → `200` **array** of `{vtypeId, typeName, capacity, isActive}` (fetched only when the create dialogs open); `POST /vehicle-types` body `{typeName, capacity}` → `201`.
- `GET /vehicles?activeOnly=true[&vtypeId=n]` → `200` **array** of `{vehId, plateNo, vtypeId, typeName, capacity, isActive}`; `POST /vehicles` body `{plateNo, vtypeId}` → `201`; `409 {code: DUPLICATE_PLATE, message}` displayed verbatim.
- Driver list: `GET /roles` (array) → roleId of `roleName == 'DRIVER'` → `GET /employees?roleId=3&activeOnly=true&page=1&pageSize=200` → `PagedEmployeeList {items, total, …}` (master module repository reused; OpenAPI defines no `/drivers` endpoint).
- Local widget tests run against an in-process fake HTTP adapter shaped exactly as above. **No live-backend interoperability is claimed.**

## Contract decisions (implementation choices made locally)
- **Q23 honored as "unavailable":** OpenAPI defines no `PUT /schedules/{schedId}` (schedule ops are GET/POST/DELETE + `PUT …/assignments` only), so no departure-edit UI, repository method, or request was implemented; a regression test asserts zero `PUT` requests reach exact `/schedules/{id}` during full interaction. UC-14.2 therefore stays unimplemented pending a requirement answer/endpoint.
- **Assignment = one combined PUT** `{empId, vehId}` per OpenAPI, not chapter-17's `POST /schedules/{id}/assign-driver|assign-vehicle` sub-resources (stale doc; same drift pattern as sprint 6's embedded-vs-subresource routes).
- **Permission model:** OpenAPI/seed define no `VEH.VIEW`/`SCHED.VIEW`. Viewing the schedule/vehicle tabs therefore requires only FrontPage access (itself gated by `ROUTE.VIEW`); mutations are gated per OpenAPI `x-permission` (`SCHED.EDIT` for create/cancel/assign, `VEH.EDIT` for vehicle/type create). Consequently a user holding only `SCHED.EDIT`/`VEH.EDIT` without `ROUTE.VIEW` cannot reach `/front` — recorded as a seed/permission-UX consideration for the coordinator; the established sprint-6 gate was not changed unilaterally.
- **Drivers** are resolved through `GET /roles` (find `DRIVER`) + `GET /employees?roleId=…` since the spec has no drivers endpoint; the master module's repository is reused rather than duplicated.
- **Vehicles are read/create only** (OpenAPI has no `PUT`/`PATCH`/`DELETE /vehicles`), so no vehicle edit/deactivate UI exists; same for vehicle types.
- AppBar title kept as `'เส้นทางและจุดจอด'` because `sprint06_test.dart:833` asserts it; with 4 tabs the title is now incomplete — cosmetic follow-up for the coordinator (changing it requires touching sprint 6's accepted test).
- `DropdownButtonFormField` uses `initialValue:` (Flutter ≥3.33 deprecation of `value:`), matching `route_editor_page.dart` convention.
