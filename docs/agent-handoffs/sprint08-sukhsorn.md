## Contract decisions (implementation choices made locally)
- **OpenAPI wins over stale docs:** usecase-spec/chapter-17 `GET /booking/available` / `POST /booking` (chapter-17:686) were NOT implemented; the client uses `GET /schedules?availableOnly` + `POST /bookings` per OpenAPI:1066/2271 (same drift pattern as sprints 6/7).
- **BR-05 is filtered client-side before display** (rounds with <20 min to the board stop's `arriveAt` are not listed, compared against board-stop arrival time, not departure): usecase-spec:329/332 requires BR-05 display filtering; OpenAPI `availableOnly` only guarantees seats. Rounds whose stops/arriveAt are missing are hidden (cannot verify → do not show). The server remains authoritative: POST re-check errors are displayed verbatim (UC-18 "server re-validates").
- **BR-06 implemented as per-booking cap** `min(4, seatsAvailable)` with UI copy 'จองครั้งละไม่เกิน 4 ที่นั่ง' — matches OpenAPI `maxSeatsPerBooking`/`BookingCreate seats 1..4` (OpenAPI:1243/2256) and `database/01_schema.sql:253` CHECK. **Cumulative per-user-per-round semantics (Q-C/Q19) is NOT settled and NOT enforced** — the API exposes no per-user bookings-per-round until T-041; see Blocked.
- **Permission:** confirm button enabled only with `BK.CREATE` (OpenAPI `x-permission`, BK.CREATE test shows steps viewable but confirm disabled and zero POST).
- **Stops loading/error surfaced** via `AsyncSection` (`LoadingState`/`ErrorState` + 'ลองอีกครั้ง' retry invalidating `stopsProvider(''))` instead of collapsing to an empty dropdown.
- **Seat-map 404 is non-fatal:** server message shown, flow continues with the schedule's `seatsAvailable`.
- Empty trip list → 'ไม่มีรอบที่จองได้ในวันนี้' (usecase-spec alt-flow wording).
- Conventions kept: `initialValue:` on `DropdownButtonFormField` (Flutter ≥3.33), `authState.can()` extension (imports `auth_models.dart`), sprint-7 harness patterns (`pumpShuttle`/`FakeBackend.on`/`jsonResponse`/`pumpFrames`), master-module `AsyncSection`/`ErrorState` keys.
