## 🟢 สิ่งที่ดีของวันนี้

1. **T-008 ปิดได้โดยไม่ต้องรออาจารย์ตอบ** — เพราะใช้หลัก "ผลบวกจริง + `TODO(Q-B)`" ตามแผนสำรองที่เขียนไว้ล่วงหน้า
2. **ทดสอบจากสคีมาว่างจริง ไม่ใช่รันทับของเดิม** — `99_drop` → `01` → `02` → `03` พิสูจน์ว่าไฟล์รันได้ตั้งแต่เริ่ม
3. **Business Rule พิสูจน์ด้วย query ไม่ใช่การดูด้วยตา** — BR-01/02/04 มี query ตรวจฝังอยู่ท้ายไฟล์ รันซ้ำได้ทุกครั้ง
4. **คำนวณเวลาให้อัตโนมัติตาม BR-01/BR-02** — ไม่ hardcode `total_minutes` และไม่ hardcode `arrive_at` แต่ใช้ correlated subquery → แก้นาทีทีเดียวทุกจุดขยับตาม
5. **Password ใน seed เป็น placeholder ที่ login ไม่ได้โดยตั้งใจ** — มี query ยืนยัน `PLAIN_PWD = 0` → ไม่มีความเสี่ยงรหัสผ่านหลุดเป็นข้อความธรรมดา (BR-SEC-1)
6. **AI นับ permission ผิดเอง (24 → 21) แต่คนตรวจจาก output จริงจึงเจอ** — เป็นหลักฐานว่า AR-05/AR-07 ทำงานจริง ไม่ใช่พิธีกรรม
7. **ข้อค้นพบเรื่องเส้นทาง 1 ถูกบันทึกไว้ในตัวไฟล์ SQL เอง** — ไม่หายไป เพราะเขียนไว้เป็นหัวข้อ 1) ของ `03_seed_front.sql` พร้อม constraint ที่ชน

## 🔎 ผลรีวิว T-008 Seed (สรุปสั้น — ฉบับเต็มอยู่ในไฟล์รีวิว)

**ผ่าน 20/22 ข้อ** — ตัวเลขทุกตัวที่นายเก่งกาญอ้างใน commit message ตรงกับที่วัดจริงบน `shuttle-oracle-xe` พอดี

| ตรวจ | ผล |
|---|---|
| จำนวนแถว master 7 ตาราง + front 9 ตาราง | ✅ ตรงทุกตัว |
| BR-01 `total_minutes` = SUM(travel) | ✅ 13 / 15 |
| BR-02 `arrive_at` สุดท้าย = depart + total | ✅ ครบ 8 รอบ |
| BR-04 คนขับ/รถชนกัน | ✅ 0 / 0 |
| RBAC: พนักงานทุกคนมี role · คนขับมี role DRIVER | ✅ 0 ข้อผิดพลาด |
| Permission ครบ 5 โมดูล | ✅ master 5 · front 4 · booking 3 · driver 3 · report 6 = 21 |
| ไม่มี object `INVALID` | ✅ 0 |
| **⚠️ `password_hash` เป็น bcrypt ยาวผิด** | **❌ 15 คน ยาว 52–54 ตัว (bcrypt ที่ถูกต้องต้อง 60) และมีแค่ 4 ค่า unique** |
| **⚠️ ไม่มีสิทธิ์ `RPT.R4`** | **❌ โมดูล report มี R1,R2,R3,R5,R6,R7 = 6 ตัว แต่ PDF กำหนดให้มี R4 (UC-28)** |

**สิ่งที่ต้องแก้ (2 เรื่อง):**
1. `password_hash` — สร้าง `bcrypt.hash()` จริง **15 ค่า ไม่ซ้ำกันเลย** ใน T-011 → ตรวจด้วย `count(distinct password_hash) = 15`
2. เพิ่ม **try/catch ตอน verify password** — เพราะ hash ยาวไม่ครบ 60 บาง library จะ `throw` ให้ API login ตอบ 500 แทน 401
3. **สิทธิ์ `RPT.R4` ไม่มี** — โมดูล `report` ข้ามเลข 4 ไป ทั้งที่ PDF กำหนดให้มี R4 (UC-28) → ต้องเลือกว่าจะ **(ก)** เพิ่มสิทธิ์ให้ครบ 7 หรือ **(ข)** ตัด R4 ออกจาก Use Case · **ต้องถามอาจารย์ก่อน** เพราะกระทบเอกสารที่ปิดแล้วทั้งคู่

> 🔎 **เรื่อง `RPT.R4` เพิ่งเจอตอนเขียน T-014** เพราะต้อง map ทุก endpoint เข้ากับสิทธิ์จริงในตาราง
> ถ้าไม่ได้เขียน OpenAPI วันนี้ ช่องว่างนี้ยังไม่มีใครเจอ
> (ส่วนเรื่อง `password_hash` คนตรวจความยาวจริงถึงพบ — AI ตรวจแค่ "ขึ้นต้น `$2b$`" แล้วผ่านไป)

**ข้อสังเกตอื่น (ไม่ผิด DoD):** `stop` จุดที่ 3 (โรงพยาบาลหนองจอก) ไม่ถูกใช้ในเส้นทางใดเลย · ไม่มีพนักงาน `is_active = 0` ทำให้ทดสอบ UC-04.3 (ปิดใช้งาน) ไม่ได้ · `booking`/`trip` ยังว่างตามขอบเขต T-008 ทำให้ BR-06/07/09/10 ยังพิสูจน์ไม่ได้

**เห็นด้วยกับการตัดสินใจของนายเก่งกาญ 3 เรื่อง:**
- ข้ามเส้นทาง 1 เพราะข้อมูลขัดแย้งเอง — หลัก AR-08 (ห้ามให้ AI เดาข้อมูล) สนับสนุน
- ใช้ 15 นาที + `TODO(Q-B)` เพราะเส้นทาง 1 (30) และ 2 (13) ตรง PDF → เป็น typo ใน PDF
- ตัดดัชนีซ้ำใน T-007 — ผลรีวิวนี้ยืนยันว่าถูกต้อง เพราะ BR-01/BR-02 คำนวณผ่านโดยไม่ต้องมีดัชนีนั้น

> ⚠️ **เรื่องที่ต้องแจ้งอาจารย์:** ข้อเสนอ (ข) ของ Q20 คือ "เส้นทาง 1 เป็นไป–กลับ" **จะกระทบ ER diagram (T-005) ที่ปิดไปแล้ว** → ต้องถามก่อนแก้ ไม่ใช่แก้เอง
