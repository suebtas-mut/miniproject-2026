## 👎 สิ่งที่ต้องปรับปรุง

- **⚠️ ตรวจ `password_hash` ไม่ลึกพอทั้งทีม** — ทั้งผู้เขียนและผู้ตรวจดูเหมือนจะเช็กแค่ "ขึ้นต้น `$2b$`"
  แล้วสรุปว่าปลอดภัย จนกระทั่งมีคนรัน `length(password_hash)` จริง
  → **15 คน ยาว 52–54 แทน 60 · unique แค่ 4 ค่า** (คนละรหัสกันใช้รหัสเดียวกัน 4 ชุด)
  บทเรียน: "หน้าตาเหมือน bcrypt" ≠ "เป็น bcrypt ที่ถูกต้อง" · **ต้องเช็กความยาวด้วยเสมอ**
- **⚠️ งานเอกสารไม่ได้ถูกตรวจเทียบกับตัวเลขจริง** — seed เสร็จแล้ว แต่ตารางสิทธิ์มี 6 รายการ
  ขณะที่เอกสารกำหนดไว้ 7 (R1–R7) → **AI ตรวจ `CREATE TABLE` / `INSERT` ครบ แต่ไม่ได้เทียบกับเอกสาร**
  ช่องว่างนี้จะไม่มีใครเจอถ้าไม่มีการ "นับทีละตัวแล้วเทียบกับสเปก"
- **ความประมาณ DoR "≤ 3 ชม." ไม่สมจริง (ค้างมาตั้งแต่ Sprint 0)** — ทั้ง 3 Task เกินเวลาแผน
  แต่เกินเพราะ **เพิ่มคุณภาพ** ไม่ใช่ทำช้า (validator, ตรวจ secret, README, ทดสอบ responsive)
  Action Item ของ Sprint 0 ที่สั่ง "แยก T-007/T-008 เป็น 2 Task ย่อย" **ยังไม่ได้ทำ**
- **DoD ผูกกับเครื่องมือที่ไม่มีสิทธิ์เข้า** — T-009 เกณฑ์ "อัปโหลด ClickUp" + "ใช้ Figma"
  ทั้งคู่ทำเองไม่ได้ แต่ยังเขียนไว้เป็นข้อ DoD → **ทำให้ Task ที่เสร็จแล้วถูกนับว่า "ยังไม่เสร็จ"**
  เป็นการเขียน DoD ที่วัดผลไม่ได้จริง
- **เอกสารบอกสถานะค้าง นอกเวลา** — `.env.example` ถูก sanitize ตั้งแต่ Sprint 0 (`cceaf4e`)
  แต่ยังถูกบันทึกว่า "มีรหัสจริง" ใน standup/checklist ทั้งที่ปิดข้อ 6.1 ได้ตั้งนาน
  → **สถานะที่ไม่ได้อัปเดต อันตรายกว่าไม่มีสถานะ** เพราะทำให้เสียเวลาแก้ของที่แก้แล้ว
- **Commit คนละ account เดียวกัน** — ทั้งสองคนใช้ numeric user ID เดียวกัน (296676037)
  → **PR ต้องรออาจารย์ review เสมอ** เพราะ GitHub ไม่อนุญาต self-approval
  ทำให้ AR-02 ("ผู้เขียนต้องไม่รีวิวงานตัวเอง") ทำได้แค่ขั้นตอนแรก
- **ตัดสินใจช่วยงานของอีกคนโดยไม่ปรึกฎเก่งกาญ** — T-014 เดิมเป็นงานของเก่งกาญ
