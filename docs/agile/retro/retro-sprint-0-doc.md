## 6. บทเรียน (Lessons Learned)

1. **DDL ในเอกสารคือแหล่งความจริงเดียวที่ต้องยึด** — การนับจำนวนคอลัมน์/Constraint ด้วยมือผิดไปถึง 3 จุด ต้องนับซ้ำจากต้นฉบับทุกครั้ง
2. **DDL ต้นทางมี `COMMENT ON` ไม่ครบทุกคอลัมน์** — ข้อ 17.4.3 มีเพียง 13 รายการ จึงเสนอฉบับเต็ม 122 รายการในบทที่ 8 และส่งต่อให้ T-007
3. **ความยาวของเนื้อหามีผลต่อความเสถียรของเครื่องมือ** — เอกสารยาวควรเขียนเป็นหลายส่วน
4. **นโยบายความปลอดภัยเป็นข้อจำกัดที่ต้องรายงาน ไม่ใช่สิ่งที่ต้อง bypass** — ตอนแรกรายงาน WDAC ให้ผู้ดูแลระบบ ปรากฏว่าสาเหตุคือ `flutter_tools.snapshot` ยัง build ไม่เสร็จ เมื่อรอให้ build จบจึงใช้งานได้ทันที **บทเรียน: ต้องแยก "อาการ" ออกจาก "สาเหตุ" ก่อนรายงานว่าเป็นปัญหาเครื่องมือ**
5. **เอกสารทุกชิ้นต้องมี Trace กลับไป Requirement** — Data Dictionary มีตารางเชื่อม UC-01…UC-30 ในหัวข้อ 8.12 เพื่อให้ตรวจสอบย้อนหลังได้
6. **ห้ามใช้รหัสเดียวกันสองความหมาย** — `AR-xx` ถูกใช้ทั้งเป็น AI Operating Rules (บทที่ 18) และเป็นสมมติฐานในเอกสารชุดนี้ จึงเปลี่ยนสมมติฐานเป็น `ASM-xx` เพื่อไม่ให้ชนกัน
