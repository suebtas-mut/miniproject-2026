#### 🔑 ข้อค้นพบสำคัญของ Sprint นี้ — Requirement ผิด 1 จุด

Requirement ระบุให้สร้างดัชนี **9 ตัว** แต่เมื่อรันจริง `ix_schedstop_sched_seq` ซ้ำกับ unique index `uq_sched_seq` ที่มีอยู่แล้ว → **`ORA-01408`**

> **คง 8 custom index** และบันทึกเหตุผลไว้ใน Prompt P-02 เพื่อไม่ให้เกิดซ้ำ
> ✅ ตัดสินใจถูก: **Requirement ผิด ไม่ใช่โค้ดผิด** — ไม่ควรยกชั้น index ทับเพื่อให้ตรงตัวเลขในเอกสาร
> ผลข้างเคียง: เอกสาร 3 ไฟล์ที่อ้างว่า "9 ดัชนี" เพี้ยนทันที → ต้องแก้ (ทำใน Sprint 2)

#### 🐛 AI ทำผิด 6 จุดระหว่างเขียน DDL (AR-07)

| # | ข้อผิดพลาด | วิธีแก้ใน P-02 |
|---|---|---|
| 1 | ใส่ `FOREIGN KEY` แบบ inline ผิด syntax | แยกเป็น named constraint |
| 2 | ตั้งชื่อ CHECK ขึ้นต้นด้วยเลข 95 (ชนกับ `NOT NULL` implicit) | ตั้งชื่อขึ้นต้น `CK_%` |
| 3 | สร้าง sequence 17 ตัวซ้ำกับ identity `ISEQ$` | ใช้ identity ที่มีอยู่ |
| 4 | ใช้ `;` ท้ายคำสั่ง ทำให้ SQL\*Plus พัง (`ORA-00933`) | ตัด `;` ในไฟล์ `.sql` |
| 5 | `DROP TABLE ... CASCADE CONSTRAINTS` ทำให้ sequence ค้าง (`ORA-32794`) | ลบ sequence แยกก่อน DROP |
| 6 | สร้าง index ซ้ำบน unique/PK อยู่แล้ว (`ORA-01408`) | ตรวจ backing index ก่อนสร้าง |

> ✅ ข้อ 1–6 ถูกย้ายเข้า Prompt **P-02 รุ่นถัดไป** ทั้งหมด (ตาม AR-06/AR-07)
